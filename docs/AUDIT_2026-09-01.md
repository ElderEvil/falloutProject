# Codebase Audit — 2026-09-01

> Findings from a full-repo quality audit (backend, frontend, tests/config).
> Each item lists evidence and a fix direction. Ranked by severity.
> Delete entries as they're addressed; keep the ranking intact for remaining items.

## 🔴 Critical

### 1. CI never tests against PostgreSQL on PRs
- `backend/app/tests/conftest.py:87` — entire suite runs on `sqlite+aiosqlite:///:memory:` with a JSONB→JSON type swap (L90–95).
- `.github/workflows/backend-ci.yml` (PR gate) provisions only Redis — no Postgres service, no `alembic upgrade head`, no `alembic check`. The nightly `backend-coverage.yml` has all of that, so PG-specific failures (enum drift, JSONB operators, migration regressions) surface at best 24h late.
- Contradiction: `docs/backend/TEST_COVERAGE_ANALYSIS.md` reports 70.93% coverage while the nightly enforces `--cov-fail-under=80` — one of them is stale or the nightly is permanently red.
- **Fix:** add a Postgres service + `alembic upgrade head` to `backend-ci.yml`; reconcile the coverage number.

### 2. Latent crash-loop trap: `task_session()` yields raw SQLAlchemy sessions
- `backend/app/db/session.py:55` — `task_session()` builds `async_sessionmaker` without `class_=AsyncSession`, so dramatiq actors get raw sessions with no `.exec()`.
- `dweller_recycling_service.py` uses `.exec()` at 9 call sites (L64, 96, 231, 265, 272, 281, 287, 293, 297); `ai_usage_service.py` at 2 (L114, 157). Currently latent (web path only), but one refactor from the documented poisoned-pool outage.
- **Fix:** add `class_=AsyncSession` to the `task_session` maker and/or migrate `.exec()` → `.execute().scalars()` in those services; add the raw-session regression test AGENTS.md requires.

### 3. Unauthenticated, state-mutating debug endpoints
- `backend/app/api/v1/endpoints/debug.py` (436 lines) — no auth dependency on any endpoint. `POST /debug/test-build-living-room/{vault_id}` (L198–299) mutates vault state; `POST /debug/emit/{vault_id}` emits arbitrary game events; L67/191 poke private `event_bus._handlers`.
- Only gated by `settings.ENVIRONMENT in ("local", "development")` (`app/api/v1/api.py:45`) — no admin fallback.
- **Fix:** require admin auth even in dev; move the "build living room" flow into a test fixture.

### 4. Dead code (~1,450 LOC deletable)
- `frontend/src/views/UITestView.vue` — 1049 lines, zero references (not routed, not imported), 62 inline `:style` bindings. Delete file + `src/views/` dir.
- ~~`backend/app/services/health_check.py` (438 lines)~~ **INCORRECT** — actively used in `main.py` (L47, L90–93, L199–200) for the `/healthcheck` endpoint. NOT dead code. (~900 LOC) stays.
- `backend/app/crud/dweller.py` — `get_revivable_dwellers` (L587–613) is never called anywhere except its own test. `death_service.py` uses its own `_get_dead_dweller_counts` query instead. Delete method + test (~60 LOC).

## 🟠 Architecture violations (project's own rules)

### 5. Business logic in endpoints and CRUD
- `backend/app/api/v1/endpoints/dweller.py:462–523` — `get_revival_cost` implements the whole domain flow inline (~15 lines); `revive_dweller` (L496) re-derives cost and re-fetches the vault, duplicating `death_service.revive_dweller`. `get_dead_dwellers` (L434–440) enriches DTOs in the endpoint. Also `restore_dweller` (L557–560) fetches before authz.
- `backend/app/crud/dweller.py` (715 lines) — game rules in CRUD: `use_stimpack` (L496), `use_radaway` (L514), `add_experience` with level-up (L330), `auto_assign_to_best_room` policy (L642), `move_to_room` (L388). Endpoints (e.g. `dweller.py:408`) call these directly, skipping the service layer.
- **Fix:** extract a dweller service (revival quote, stimpack/radaway/XP, auto-assign); CRUD keeps pure persistence. Collapses the near-duplicate dead/revival queries (L532–640) too.

### 6. Frontend API-layer bypass
- 16 stores/composables import axios directly instead of going through module `services/`: `progression/stores/quest.ts`, `objectives.ts`, `exploration/stores/exploration.ts`, `vault/stores/vault.ts`, `dwellers/stores/{dwellerGeneration,dwellerManagement,dwellerMedical,dwellerFilter,dwellerDeath}.ts`, `rooms/stores/room.ts`, `profile/stores/profile.ts`, `social/stores/{relationship,pregnancy}.ts`, `radio/stores/radio.ts`, `rooms/composables/useRadioRoom.ts`, `chat/composables/useChatMessages.ts`.
- Inconsistent even within one module (e.g. `progression` has both patterns side-by-side).
- **Fix:** module-by-module, move HTTP calls into `services/`; stores consume services. Start with `progression`.

### 7. God services & duplicated ownership checks
- `backend/app/services/game_loop.py` (891 lines, 16 except blocks) — resource ticks, leveling, death, objectives, notifications in one module; function-level imports (L309, 359, 419) signal circular deps. Extract death-tick and leveling-tick into `death_service`/`leveling_service`.
- `backend/app/services/chat_service.py` (659 lines, 11 except blocks) — repeated `ModelHTTPError` + bare `except Exception` ladders (L264–275, L529–535, L551–558) as control flow. One helper mapping provider errors → user-facing responses.
- Hand-rolled ownership checks parallel to deps helpers: `death_service.py:135`, `chat_service.py:647` — run *alongside* `verify_dweller_access`, so the check runs twice with different implementations. Extract a shared `assert_vault_owner(vault, user)` or trust the deps layer.

## 🟢 Cheap cleanups

### 11. docker-compose drift (3 files)
- Postgres volume: `infra.yml:11` mounts `/var/lib/postgresql`; the other two mount `/var/lib/postgresql/data` — not equivalent for `postgres:18-alpine`.
- rustfs: ports differ (infra `9002/9003` vs local `9000/9001`); only `docker-compose.yml` wires credentials + healthcheck.
- dramatiq: `infra.yml:56` has orphan cleanup; `local.yml:43` orphans periodiq on exit.
- Cruft: `docker-compose.yml:54` gives redis `env_file: .env` (ignored by the image).

### 12. Inline `:style` theme hack (~15 files, 155 occurrences)
- Dominant pattern: `:style="{ color: 'var(--color-theme-primary)' }"` — 13× in `PreferencesView.vue`, 11× in `VaultList.vue`, 8× in `HappinessDashboard.vue`, etc. A missing-utility problem, not 155 mistakes.
- **Fix:** add `text-theme-primary` / `text-theme-accent` / `border-theme-glow` utilities in `assets/tailwind.css` (`@utility`), then mechanically replace. Only PreferencesView's dynamic theme bindings are legitimately runtime.

### 13. Type-safety cluster: `as any`
- `storage/components/StorageItemCard.vue` (9×) — item union unmodeled; needs a discriminated union (`WeaponItem | OutfitItem | …`) in `modules/storage/models/`.
- `TrainingStartModal.vue` — `(dweller as any)[stat.short]`; add stat short-keys to the dweller model.
- No `@ts-ignore` anywhere (good).

### 14. Swallowed errors & duplication (frontend)
- Silent `catch {}` in `profile/views/ProfileView.vue:125,143`; bare `catch {` in `ArenaModal.vue` (~L161, ~L197) around unassign/heal. Route through `errorHandler.ts`.
- `stat-card`/`stat-value` markup + CSS copy-pasted in 13+ components → one `core/components/ui/UStatCard.vue`.
- Giant components: `DwellerAppearanceEditor.vue` (737, 387-line script → `useAppearanceEditor()`), `QuestCard.vue` (791, per-card `setInterval` timers → shared `useCountdown()`), `ArenaModal.vue` (837, cross-module orchestration → `useArenaFightFlow()`).
- CSS-bloat (lower priority): `CombatModal.vue` ~340 lines scoped CSS, `ExplorationView.vue` 323-line style block — fold into shared CRT classes.

### 15. Repo hygiene (minor)
- `.gitignore`: root `logs/` only ignored incidentally via `*.log`; explicit entry is `backend/logs/`. `.uv-cache/` not listed. `.codegraph` only in local `.git/info/exclude`. Stock multi-template dump (Django/Flask/Scrapy sections irrelevant).
- CI: `backend-coverage.yml` pins action SHAs; `backend-ci.yml`/`frontend-ci.yml` float `@v7`. `frontend-ci.yml:52` uses `pnpm run test -- --run` instead of the designated `test:run`.
