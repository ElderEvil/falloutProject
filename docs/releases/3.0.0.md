## 5. Maintenance window

Requires `maintenance_mode=true`, `run_migrations=true`, `public_traffic_gate=true` and
`preflight_only=false`. The `production-migration` environment must have a required reviewer and
wait timer; it is configured in repository settings.

```bash
gh workflow run deploy-hetzner.yml \
  -f image_tag=v3.0.0 \
  -f run_migrations=true \
  -f maintenance_mode=true \
  -f public_traffic_gate=true
```

The `prepare` job stops API/worker writers, creates the verified pre-migration dump and closes
public ingress, then waits on the protected `production-migration` environment. Approve it only after
restoring and rehearsing the exact dump from step 4. If the rehearsal fails, reject the environment;
the cleanup job restores the original replica counts and ingress. If the migration itself fails after
approval, the migration-started marker keeps writers stopped and public ingress closed for manual
recovery.

## 6. Operator verification

Use `kubectl exec` or `kubectl port-forward` against the backend:

- revision is `4b3cbd7b15ff`; 122 application `timestamptz` columns (the three
  `pg_stat_statements` extension columns are separate);
- preserved instants and NULLs match the pre-migration snapshot;
- one real vault tick completes;
- API timestamps end in `Z`; SSE replay and notification dedup work;
- a legacy v4 ID still resolves;
- desktop and phone date displays are correct;
- error-level logs are empty for 10 minutes.

## 7. Open public traffic

```bash
gh workflow run open-public-traffic.yml -f confirm=open
```

Only after step 6 passes.

## 8. Rollback

Keep the pinned **v2.295.1** images and the verified pre-migration dump.

- Before/after a committed schema change, recovery is a **restore** of that dump with the matching
  v2 image, revision and configuration; `alembic downgrade` alone is not sufficient.
- Rolling back after new player progress discards post-window activity. State this in the release
  notes; keep a post-failure backup and require an explicit reconciliation decision.
- Do not replace the stored JSON history or identity strings during recovery.
