# 3.0.0 release runbook

Status: **prepared, not executed**. Do not start the window until:

- #1380, #1381, #1382 and #1383 are merged in order;
- the production-clone restore/migrate/tick/rollback rehearsal has been recorded;
- an operator has approved the maintenance window and the public-traffic gate.

Latest pre-3.0 tag at authoring time: **v2.296.0**. Re-record the last verified tag and image
digests at the actual window; do not rely on this snapshot.

## 1. Merge the stack

1. #1380 `feat(time): switch persistence to aware UTC`
2. #1381 `chore(deps): upgrade SQLModel 0.0.48 and SQLAlchemy 2.1`
3. #1382 `docs(deploy): record B6 aware-UTC restore rehearsal`
4. #1383 `feat(auth): replace passlib with pwdlib and rehash on login`

After each merge, retarget the next PR to `master` before merging it.

## 2. Emit the major version

Semantic Release owns the version and tag. Add one commit on `master` with a
`BREAKING CHANGE:` footer; do not hand-create a tag and do not edit the version files.

```text
feat(release)!: ship the 3.0 platform boundary

BREAKING CHANGE: Python 3.14 is required; persisted timestamps use timezone-aware
timestamptz; SQLModel 0.0.48 / SQLAlchemy 2.1; passlib is replaced by pwdlib/Argon2
with bcrypt rehash-on-login.
```

Wait for the Release workflow to publish `v3.0.0` and build both images.

## 3. Preflight (read-only)

```bash
gh workflow run deploy-hetzner.yml \
  -f image_tag=v2.296.0 \
  -f preflight_only=true
```

Capture the production schema revision, timestamp-column inventory, row counts and capacity.

## 4. Production-clone rehearsal

The local B6 evidence (`docs/backend/B6_REHEARSAL.md`) is not a production-clone proof.
Restore the production dump into isolated infrastructure, run `4b3cbd7b15ff`, boot the pinned
`v2.296.0` image, exercise a tick, then rehearse rollback to the pre-migration snapshot.
Record timings and the exact image/revision pair.

## 5. Maintenance window

Requires `maintenance_mode=true`, `run_migrations=true`, `public_traffic_gate=true` and
`preflight_only=false`.

```bash
gh workflow run deploy-hetzner.yml \
  -f image_tag=v3.0.0 \
  -f run_migrations=true \
  -f maintenance_mode=true \
  -f public_traffic_gate=true
```

The workflow stops API/worker writers, verifies the pre-migration dump, closes public ingress and
runs the Alembic revision. Public traffic stays blocked after automated checks.

## 6. Operator verification

Use `kubectl exec` or `kubectl port-forward` against the backend:

- revision is `4b3cbd7b15ff`; 122 `timestamptz` columns;
- preserved instants and NULLs match the pre-migration snapshot;
- one real vault tick completes;
- API timestamps end in `Z`; SSE replay and notification dedup work;
- a legacy v4 ID still resolves;
- desktop and phone date displays are correct;
- error-level logs are empty for 10 minutes.

## 7. Open public traffic

```bash
gh workflow run open-public-traffic.yml -f confirm=open
```

Only after step 6 passes.

## 8. Rollback

Keep the pinned **v2.296.0** images and the verified pre-migration dump.

- Before/after a committed schema change, recovery is a **restore** of that dump with the matching
  v2 image, revision and configuration; `alembic downgrade` alone is not sufficient.
- Rolling back after new player progress discards post-window activity. State this in the release
  notes; keep a post-failure backup and require an explicit reconciliation decision.
- Do not replace the stored JSON history or identity strings during recovery.
